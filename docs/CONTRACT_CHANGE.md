# 设计契约变更

日期：2026-11-14  
提出：用户  
执行：Claude Code  
范围：`docs/DESIGN.md` 与 `src/styles.css`；不改业务逻辑、数据层、路由、文案键和云端状态契约。

## 现状

S1 设计采用奶油色纸张、杏色卡片、Lotus 红色强调与香槟色边框。视觉语言偏温暖纪念册，组件已经完整，但用户要求重新定稿。

## 变更原因

用户指定以黑白简约为主色调，并要求参考 `senlindesign/taste-skill` 的取舍方法。黑白色不是简单移除暖色，而是让层级由字号、字重、1px 线、留白和照片本身建立。

## 新方向

- 名称：黑白编辑档案册。
- 页面：冷白纸面，不使用装饰性渐变、彩色强调或悬浮光效。
- 主色：近黑；辅助色：中性灰；边界：细墨线。
- 照片：像 contact sheet / 小型展览，不使用随机旋转与厚相框。
- 字体：一个无衬线正文系统和一个宋体标题系统；标题依靠尺寸与字重，不依靠颜色。
- 动效：只保留状态反馈与照片反馈，120–260ms。
- 保留：所有功能、固定状态槽位、44px 触控区、375px 无横向滚动、可访问焦点和 `prefers-reduced-motion`。

## 取舍

1. 用严格黑白层级，不用一个低饱和品牌色。代价是不能再靠颜色区分操作层级，按钮主次必须通过实心/描边和排版表达。
2. 用有意的纸面留白与细分隔线，不做每块内容都装进卡片。代价是页面纵向更长，浏览节奏更慢。
3. 照片去掉随机旋转和厚阴影，改为对齐的编辑网格。代价是牺牲手作感，换取照片陈列秩序。
4. 标题改用宋体，正文使用系统中性无衬线。代价是字体组合比单一字体更传统，但能保留纪念册语义。

## 验收影响

- A17、A18、A19、A21、A22 仍适用。
- A18 的六色 token 改为黑白灰六值，仍保持“一个用途一个 token”。
- 不新增页面、按钮、弹窗或依赖。
- 所有云端状态句与交互行为保持原样。

## 回滚

回滚点为当前 `src/styles.css` 与 `docs/DESIGN.md` 的修改前版本；不涉及数据库迁移或用户数据。

## 变更 2：关闭注册与单一共享账号

日期：2026-11-14  
提出：用户  
范围：`SPEC.md`、`DESIGN.md`、`COPY.md`、`CLOUD_STATES.md`、`ACCEPTANCE.md`、`LIB_API.md`、认证数据层、RLS 与 Storage 策略。

### 原因

用户确认放弃“半公开 + 开放 RLS”和前端仪式性暗号门禁，改为 Supabase Auth 邮箱密码登录。网站关闭自助注册，Supabase Auth 只保留一个由站点所有者提供的共享账号；知道网址的人还需要取得这组账号密码才能进入。

### 新权限模型

1. 未登录访客只能看到公开视觉壳层、登录入口与安全占位内容，不请求三表数据或私有照片。
2. Supabase Auth 关闭公开注册；邮箱密码只由 Supabase Auth 验证，网站不显示注册、邀请或新增账号入口。
3. 不建立 `allowed_users` 白名单，也不按用户隔离数据；部署时 Auth Users 只保留一个共享账号。
4. `photos`、`memories`、`messages` 与 `memories` Storage 桶只允许 `authenticated` 用户读写；`anon` 无策略、无表权限。
5. `service_role` 不进入浏览器、构建产物、文档或 Git。

### 静态层边界

- 公开占位壳层仍可静态优先渲染，断网不得白屏。
- 真实照片、时光与留言只从受 RLS/Storage 保护的云端读取，不得复制到 `public/`、`dist/` 或 Service Worker 缓存。
- 已登录后的文本快照可保存在本机；退出登录必须清除。
- Service Worker 只预缓存公开壳层，不缓存 Supabase JSON、签名地址或受保护媒体。

### 回滚

应用层可回退到上一版认证适配器；数据库回滚需要重新创建旧开放策略，只允许在确认没有真实私密数据且经站点所有者批准后执行。默认回滚点不包含数据删除。

## 变更 3：暖米纸编辑部视觉

日期：2026-11-14
提出：用户
参考：用户提供的 Editorial Magazine 风格规范；本机 `stylekit` MCP 已连接，但远程查询返回 429，未将其返回内容作为实现依据。

### 目标

保留全部 Auth、数据、照片、音乐、导出和六状态功能，只重做视觉层。页面从黑白档案册升级为暖米纸上的衬线杂志版面：更强字号级差、更多留白、发丝线分区、无圆角、无阴影、无渐变；陈玫色只用于少量爱心与选中态。

### 新视觉口径

- 画布 `#F9F8F6`，主文字和线框 `#1C1C1C`，辅助文字 `#6B7280`，唯一彩色 `#816D70`。
- 标题统一衬线；正文、按钮、标签统一无衬线。
- 显示标题桌面 72px，区域标题 48px，正文 16px，标签 12px。
- 页面最大宽度 1200px；区块间距 96px；容器内边距移动端 24px、桌面 48px。
- 所有卡片、按钮、输入框、照片与弹层圆角为 0；普通元素无阴影、无渐变。
- 照片保持不规则节奏与每 7 张一张 `3:2` 跨列主照片；装饰仍为线稿气球与小面积爱心。
- 背景音乐、导航、门禁、退出、上传、删除、导出和状态槽的位置及行为保持不变。

### 明确不做

- 不重做数据模型、Auth 流程、RLS、Storage 或 Service Worker。
- 不新增内容页、社交互动、深色模式、第三方字体或动画库。
- 不使用大块陈玫色、纯黑 `#0A0A0A`、冷白 `#FAFAFA`、渐变、光晕和装饰几何。

## 变更 4：照片节奏、庆祝点缀与背景音乐（已并入 v5）

日期：2026-11-14  
提出：用户  
范围：`DESIGN.md`、`COPY.md`、照片墙、主站页头、背景音乐资源和 `ACCEPTANCE.md`。

### 原因

用户要求 UI 进一步美化，照片排布不要过于单一，并加入适量黑白气球和庆祝爱心点缀；同时加入可自定义的背景音乐。v5 将爱心颜色统一为陈玫色 `#816D70`。

### 新视觉方向

1. 保留杂志编辑体系，使用唯一彩色 token `mauve #816D70`，只用于爱心、选中态和极小面积强调，不用于正文、按钮或状态。
2. 照片使用无圆角网格，每 7 张形成一次节奏变化：一张横跨两列，一张向下错位，避免均匀重复。
3. 照片区标题下加入纸片感黑白气球和少量陈玫色爱心；装饰不进入可访问树，不覆盖照片或操作。
4. 登录后页头提供“背景音乐”播放按钮。浏览器要求首次播放由用户点击触发，因此不自动强制播放。
5. 默认音轨为原创合成氛围循环 `public/audio/memory-theme.wav`，可通过 `VITE_BACKGROUND_MUSIC_URL` 替换为站点所有者有权使用的自定义音乐。

### 回滚

移除 `BackgroundMusic`、音频资源与 `photo-feature` / `photo-offset` / `photo-scrapbook` 样式即可恢复 v3；不影响 Supabase 数据或认证。

## 变更 5：可上传背景音乐

日期：2026-11-14
提出：用户
范围：`SPEC.md`、`DESIGN.md`、`COPY.md`、`ACCEPTANCE.md`、音乐数据层、设置界面与 Storage。

### 原因

用户要求背景音乐可以直接从网站上传，不再只依赖替换源码中的音频文件。

### 新行为

1. 登录后页头保留播放/暂停按钮，并新增“换音乐”设置入口。
2. 支持 MP3、WAV、M4A，单文件不超过 16MB。
3. 音乐上传到私有 `music` Storage 桶的 `theme/` 目录，只有 authenticated 用户可读写；使用短期签名 URL 播放。
4. 新音轨覆盖当前音轨；其他旧音轨自动清理。另一台设备登录后从同一私有桶读取并重新签发地址。
5. “恢复默认”删除自选音轨并切回打包的 `audio/memory-theme.wav`。
6. 首次播放仍需用户手势；上传成功后可在同一次用户操作中开始播放。

### 回滚

停止读取 `music` 桶并删除设置入口即可退回只能使用打包默认音轨的版本；迁移可保留，不影响照片和业务数据。

提出：用户

1. 登录后的首屏升级为完整杂志封面结构，保留站名、题句、天数、音乐和退出入口，并增加“翻开照片”主导航动作。

## 变更 7：云端留言删除

日期：2026-11-14
提出：用户
范围：`SPEC.md`、`COPY.md`、`ACCEPTANCE.md`、总验收表、留言列表、主站删除状态与数据层。

### 原因

原留言板只支持新增；用户需要把误发或不再保留的云端留言从共享纪念空间移除。

### 新行为

1. 云端留言显示“移走这条”，静态内置留言不显示删除入口。
2. 删除沿用照片与回忆共用的二次确认弹层，标题明确为“要把这条留言移走吗”，确认文案为“移走”。
3. 取消、Escape 或离线状态不发起删除；确认后调用 authenticated `messages.delete`，成功后立即从列表和本地文本快照状态中移除。
4. RLS 继续使用现有单共享账号的 authenticated 策略，不新增匿名权限、不改数据表结构。

### 回滚

移除留言删除按钮与 `CloudStore.deleteMessage` 即可回到只能新增留言的版本；不涉及数据库迁移或既有数据回滚。

## 变更 8：混合相框与相片库

日期：2026-11-14
提出：用户
范围：`PhotoWall.tsx`、`copy.ts`、`styles.css`、`SPEC.md`、`COPY.md`、`ACCEPTANCE.md`、总验收表。

### 原因

用户希望照片位置与尺寸更多样，提供多个相框，并能从一个相片库集中查看全部照片。

### 新行为

1. 照片墙循环使用五种编辑相框：黑色细框、白卡纸、双线框、深墨框和灰纸内衬。
2. 每 7 张首张作为独立整行 3:2 主图；其余照片按高度权重分配到 2/3/4 个均衡列桶，并混合普通 4:5、方幅 1:1、竖幅 3:4 与向下错位节奏。
3. 照片区新增“相片库”入口；弹层使用列式 contact sheet 展示全部照片，点击后进入现有大图查看、删除和二次确认流程。
4. 相片库复用已有照片数据和签名地址缓存，不复制媒体、不增加新表，也不改变上传与删除权限。

### 回滚

移除相片库入口与弹层，并删除 `frame-*`、`photo-square`、`photo-tall` 和 `photo-library-*` 样式即可回到单一编排列版本；Supabase 数据不受影响。
