# 私人纪念空间功能规格

版本：v4.0  
存储：Supabase Auth + 数据库 + 私有 Storage  
核心参数：称呼 `<HER_NAME>`；纪念起始日 `<START_DATE>`；唯一共享登录邮箱 `SHARED_AUTH_EMAIL`；密码只由 Supabase Auth 管理

## 1. 产品边界

这是只允许持有共享登录凭据的访客访问的私人纪念空间，不是社交产品。未登录时，私密纪念内容不得挂载、请求或出现在 DOM 中。首次打开先显示公开壳层与邮箱密码登录信；Supabase Auth 验证成功后进入包含照片墙、时光轴和留言板的主站。

公开壳层与安全占位内容可以随站点静态发布并立即出现；真实照片、时光和留言只从受 RLS/Storage 保护的云端异步加载。任何认证、云端或离线状态都不得让公开壳层白屏或变成整页技术错误遮罩。

前端不保存固定账号暗号，也不提供注册入口。Supabase Auth 关闭公开注册，部署项目只保留一个共享账号；拿到站点地址和 publishable key、但没有共享账号密码的匿名访客不能读取或写入私密数据。

## 2. 内容实体

- 照片：`id`、`filename`、`takenAt`、可选 `note`、`src`。静态照片的 `src` 指向站点内文件；云端照片的地址只能由运行时签名结果提供。
- 时光轴条目：`id`、`date`、`title`、`body`、可选 `photoId`。
- 留言：`id`、`text`、`createdAt`。
- 站点头信息：`herName`、`startDate`、`openingLine`、`passHint`。
- 云端与静态条目以 `id` 去重；同 `id` 时云端优先。照片按 `takenAt` 倒序，时光轴按 `date` 倒序，留言按 `createdAt` 倒序。

## 3. 功能规格

### F-01 邮箱密码登录页
入口：没有有效 Supabase Auth 会话时访问站点根路径。  
行为：显示一封“未拆开的信”；邮箱与密码沿两条书写线输入；提交后只由 Supabase Auth 验证，成功后进入主站。  
边界：邮箱提交前去掉首尾空格；密码保持原值；页面不保存固定暗号，也不提供注册入口；错误凭据只显示统一提示。  
失败：无效凭据回到登录页；网络失败只显示可重试的公开状态，不挂载私密内容。

### F-02 首屏开启
入口：通过 Auth 校验后的首次主站会话。  
行为：进入主站后加载受保护内容，再播放一次拆信展开动效，280ms 后进入可操作状态；用户可点击“直接进入”跳过。  
边界：每个浏览器会话最多播放一次；`prefers-reduced-motion` 下直接显示，不等待动效。  
失败：动效资源不可用时直接显示主站；不得让动效阻塞照片、文字或键盘操作。

### F-03 照片批量上传
入口：照片墙顶部“添加照片”按钮；照片墙空状态中央按钮。  
行为：一次选择或拖入最多 20 张图片，逐张压缩到长边不超过 1600px、WebP 质量 0.82，再上传并插入照片墙；每张显示独立进度，成功后高亮 520ms。  
边界：单张原文件超过 8MB 时在本地拒绝，不发起网络请求；允许 JPEG、PNG、WebP；单张压缩后仍超过 8MB 时同样在本地拒绝；同批次单张失败不回滚其他成功项。  
失败：本地解码或压缩不成功时，仅该张显示重试入口；空间已满时停止后续上传并引导导出；离线或云端暂不可用时保留已成功项，未上传项可重试。

### F-04 照片墙
入口：主站默认内容区。  
行为：375px 为 2 列，768px 为 3 列，1200px 为 4 列；每 7 张照片安排一张跨两列的 3:2 主照片，并可有一条向下错位节奏，其余保持 4:5；照片带拍摄日期与可选说明；点击照片打开只读大图查看层。  
边界：标题与网格间可出现不可交互的两枚黑白纸片气球和两枚小面积陈玫色爱心；装饰不得遮挡内容。图片懒加载；每张都有可读替代文本；大图可用 Escape 关闭，焦点返回原照片；无照片时进入 F-10。
失败：单张签名地址不可用时显示同尺寸纸张占位与说明，不影响其他照片；整组云端照片不可用时保留公开壳层、已认证会话的本地文本快照和可理解的降级提示，不展示未授权内容。

### F-05 照片或回忆删除
入口：照片大图查看层与时光轴条目菜单。  
行为：点击删除后先显示二次确认；确认成功后从当前列表移除，并在 520ms 内给出可理解的结果提示。  
边界：一次只删除一个对象；确认框必须明确对象标题或拍摄日期；取消不产生请求。  
失败：离线时禁用删除并说明当前只能浏览；云端不可用时保留当前可见内容并允许稍后重试，不先做假删除。

### F-06 纪念物件增删改
入口：时光轴顶部“写下这一刻”。  
行为：新建或编辑一条纪念物件，字段为日期、标题、正文、可选照片；标题最多 30 字，正文最多 500 字；保存后按日期插入时光轴。  
边界：日期必须为有效 `YYYY-MM-DD`；标题和正文去首尾空格；空白标题不得保存；可选照片只能引用已成功上传的照片。  
失败：云端写入不成功时保留表单草稿并显示重试入口；离线只允许浏览；不得清空已输入文字。

### F-07 时光轴
入口：主站“时光”区域。  
行为：按日期倒序展示静态与云端条目；桌面为左侧日期、右侧内容，移动端为单列；可选照片宽度不超过内容列。  
边界：同一天多条按创建时间倒序；跨年日期显示年份；长正文最多展示 8 行，可展开。  
失败：静态条目始终可见；云端增量不可用时在列表尾部保留固定高度提示位，不插入空白时间节点。

### F-08 留言板
入口：主站“留言”区域。  
行为：输入最多 500 字并提交；成功后在列表顶部插入并清空输入框；静态留言与云端留言合并展示。  
边界：去首尾空格；空内容不得提交；保留换行，以纯文本显示；提交按钮在请求期间只禁用一次。  
失败：云端不可用时保留草稿，允许重试；空间满时停止提交并引导导出；离线时输入框可见但提交禁用并说明当前只能浏览。

### F-09 彩蛋
入口：首屏标题下方的小型日期印章。  
行为：点击后展开一句“今天是在一起的第 N 天”；N 按本地自然日计算，起始日当天为第 0 天。  
边界：同一天只展开一次，再次点击收起；日期跨月、跨年按真实日历计算；只使用静态站点头信息。  
失败：起始日期缺失或无效时不显示入口；不得猜测日期，也不得影响主站其他功能。

### F-10 空状态
入口：照片墙、时光轴或留言板没有可见条目时。  
行为：用一张留白信纸和一句简短邀请替代空白；照片区提供添加入口，时光区提供记录入口，留言区聚焦输入框。  
边界：空状态高度与该区域最小高度一致，出现或消失不引起页面跳动；静态内容为空但云端加载中时先显示骨架屏。  
失败：云端降级时优先显示本地已有内容；确实无内容时才显示空状态，且不得同时叠加加载提示和空状态。

### F-11 一键导出
入口：主站页脚“带走一份备份”与空间满提示中的同一入口。  
行为：收集静态与云端文本，逐张下载云端照片，生成一个包含 `content.json`、`photos/` 和说明文件的 zip；下载文件名使用 `memories-YYYY-MM-DD.zip`。  
边界：导出不改变线上数据；照片文件按原存储路径命名；重复导出覆盖同一日文件名；导出期间按钮显示进度并防止重复点击。  
失败：任一步不成功时保留已获取的数据并允许重试；zip 生成不成功时不得显示“已导出”；下载被浏览器阻止时给出面向用户的下一步说明。

### F-12 云端状态与降级
入口：主站异步加载、写入、上传或网络环境变化。  
行为：应用总状态为 `LOADING / READY / DEGRADED / PAUSED / QUOTA / OFFLINE`；静态内容在所有状态下先显示且持续可见；云端增量区域按 `CLOUD_STATES.md` 替换，不遮住主站。  
边界：`LOADING` 只表示首次云端拉取，不得挡住静态内容；`DEGRADED` 与 `OFFLINE` 提供重试，`PAUSED` 不提供无效重试；`QUOTA` 只作用于写操作并始终保留已成功内容；单张文件超过 8MB 使用独立的 `FILE_TOO_LARGE` 原因，不把本地校验混同云端空间满。  
失败：不得白屏、不得整页 Modal、不得整页遮罩、不得叠放多个 toast、不得让重试动画超过 3 秒、不得改动已经渲染的静态内容尺寸。任何云端提示只使用 `COPY.md` 中的对应文案。

### F-13 背景音乐
入口：登录后的主站页头“背景音乐”按钮。  
行为：点击播放或暂停一条低响度循环音轨；播放偏好保存在本地，刷新后尝试恢复；浏览器拒绝自动恢复时保持暂停并等待用户再次点击。  
边界：默认使用 `public/audio/memory-theme.ogg`；站点所有者可通过 `VITE_BACKGROUND_MUSIC_URL` 或替换文件使用自定义音轨；不新增第三方音乐服务请求。  
失败：音频缺失或解码失败时按钮显示“音乐待替换”并禁用；不得影响登录、照片、时光、留言或导出。

## 4. 跨模块契约修订

这些条款覆盖提示词中的类型歧义，DeepSeek 与 CodeBuddy 必须按此实现：

1. 照片签名地址失败时返回空值，不抛异常；因此接口返回“字符串或空值”，UI 负责显示占位。
2. 云端状态是应用级聚合状态，单个数据方法通过可分类错误表达操作结果；控制器捕获后更新聚合状态。
3. 导出所需照片必须带存储路径与 Blob 的成对元数据，不能只返回无序 Blob 列表。
4. 图片压缩结果必须包含实际输出格式，供上传扩展名与 MIME 类型使用。
5. zip 打包属于导出闭环的必要能力。允许 CodeBuddy 增加仅在用户点击导出后动态加载的 `jszip`，不得为此引入其他依赖；若坚持零额外依赖，则必须删除 F-11 与 A28，不能宣称可导出。

## 5. 明确不做

- 不做深色模式：单一纸张气质更完整，减少首版状态与测试面。
- 不做多语言：内容全部为两个人使用的中文。
- 不做公开注册、邀请、账号切换或多账号管理：项目只保留一个共享 Supabase Auth 账号。
- 不做点赞、评论、分享、关注：纪念空间不需要社交反馈。
- 不做管理后台：编辑操作在内容所在区域完成。
- 不做地图、音乐自动播放与视频：扩大资源体积且偏离核心回忆浏览。
- 不做无限滚动瀑布流：时间与照片数量有限，完整可扫描比停留时长重要。
- 不做 PWA 与离线写入：离线只保证已加载/静态内容可读，避免冲突合并。

## 已确认决策

1. 权限模型为关闭公开注册、单一共享 Supabase Auth 账号；匿名用户由 RLS 拒绝。
2. 部署平台为 GitHub Pages；真实远程发布仍需单独授权。
3. F-11 允许在用户点击导出后动态加载 `jszip`，不增加其他未批准依赖。
